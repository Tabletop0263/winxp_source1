# Wii Hardware Testing Guide - XP (NT 5.1) Broadway/G3 Port

This guide walks through testing the Windows XP (NT 5.1) PowerPC Broadway/G3
kernel on a real Nintendo Wii via the Homebrew Channel and a FAT32 SD card.

## Prerequisites

- A Nintendo Wii with the Homebrew Channel installed.
- A FAT32-formatted SD card (SD or SDHC, up to 32 GB recommended).
- A PC to format the SD card and copy files.
- The CI-built SD package (`wii_sd/`) produced by `.github/workflows/build-wii.yml`.

## CI-produced files (built by build-wii.yml)

| SD path | Source | Description |
|---|---|---|
| `sd:/apps/arcldr/boot.dol` | `entii/arcldr/arcldr_rvl.dol` | entii arcldr DOL loader (launched from Homebrew Channel) |
| `sd:/nt/arcfw.elf` | `Source/XPSP1/NT/base/build/ppc/ntoskrnl_le.elf` | XP kernel (ELF32 little-endian) |
| `sd:/README.md` | generated by CI | These testing instructions (also embedded in the SD image) |

The CI workflow (`Package Wii SD card layout` step) creates:

```
wii_sd/
  README.md
  nt/
    arcfw.elf
  apps/
    arcldr/
      boot.dol
```

## Step 1 - Format the SD card as FAT32

1. Insert the SD card into your PC.
2. Format the entire SD card as a single FAT32 partition.
   - On Windows: use `format X: /FS:FAT32` or Disk Management.
   - On Linux: `mkfs.vfat -F 32 /dev/sdX` (replace `sdX` with your device).
   - On macOS: Disk Utility → Erase → MS-DOS (FAT).
3. Confirm the card has a single FAT32 partition and is not write-protected.

## Step 2 - Copy wii_sd/ contents to the SD card root

Copy the *contents* of `wii_sd/` (not the `wii_sd/` folder itself) to the root
of the FAT32 SD card:

```
sd:/
  README.md
  nt/
    arcfw.elf
  apps/
    arcldr/
      boot.dol
```

Safely eject/unmount the SD card from your PC.

## Step 3 - Insert the SD card into the Wii

1. Power off the Wii completely.
2. Insert the FAT32 SD card into the Wii's SD card slot (front or rear,
   depending on model).
3. Power the Wii on.

## Step 4 - Launch the Homebrew Channel

1. From the Wii System Menu, launch the Homebrew Channel.
2. The Homebrew Channel scans `sd:/apps/` for `.dol`/`.elf` applications.
3. You should see `arcldr` listed (from `sd:/apps/arcldr/boot.dol`).
4. Select `arcldr` and press A to launch it.

## Step 5 - Run arcldr from the Homebrew Channel

arcldr is entii's GameCube/Wii loader. On launch it:

1. Opens `sd:/nt/arcfw.elf` from the FAT32 SD card (via libfat).
2. Reads the ELF32 little-endian kernel image into memory.
3. Builds a `PHW_DESCRIPTION` structure describing the Wii's hardware
   (framebuffer base/width/height/stride, decrementer frequency, memory map).
4. Enters little-endian mode (MSR_ILE) and jumps to the XP kernel's `_start`
   entry point via `ModeSwitchEntry`, passing the `PHW_DESCRIPTION` pointer
   in GPR r3.

## What arcldr does after loading the kernel

- `arcldr` loads `sd:/nt/arcfw.elf`.
- Builds `PHW_DESCRIPTION` from Wii hardware.
- Jumps to `_start` (XP kernel entry) with r3 = PHW_DESCRIPTION pointer.
- The kernel entry stub (`ntos_entry.S` / `_start`):
  - Saves the loader block pointer.
  - Loads the PCR address into GPR r2.
  - Calls `KeInitializeKernel(r3)`.
- `KeInitializeKernel` → `KeInitializeKernelPpc` performs PPC-specific init:
  - PCR installation, exception vector setup, Decrementer setup.
  - Framebuffer display initialization.
  - Wii PAD (Serial Interface) controller initialization.

## Expected behavior on real hardware

Once the kernel boots, the following should appear on screen:

```
Windows XP (NT 5.1) - PowerPC Broadway/G3 Port
Kernel initialized. Boot phase complete.
Controller input initialized.
```

Success criteria (see "What success looks like" below):

- Text appears on the screen via the framebuffer driver.
- "Kernel initialized. Boot phase complete." is printed.
- "Controller input initialized." is printed.
- The Wii does not immediately reboot or crash.
- PAD buttons can be read (no shell yet to act on them).

## Troubleshooting

### What if the screen stays black?

- Confirm the SD card is FAT32 (not exFAT/NTFS/HFS+).
- Confirm `sd:/apps/arcldr/boot.dol` and `sd:/nt/arcfw.elf` exist and are
  not zero-length.
- Confirm you launched `arcldr` (not another homebrew app) from the
  Homebrew Channel.
- The framebuffer defaults to 640x480 RGB565 via libogc; if your TV/mode
  differs, text may render off-screen. Try a different display mode or
  component cable.
- The kernel may hang before `HalpDisplayInit` if `PHW_DESCRIPTION` is
  malformed. Check the arcldr build and ELF copy.

### What if the Wii reboots immediately?

- A reboot right after launching arcldr usually means the kernel faulted
  during `_start` or `KeInitializeKernelPpc` (e.g. bad vector page, bad PCR
  setup, or an exception with no handler).
- Confirm `arcfw.elf` is the ELF32 little-endian build (`Class: ELF32`,
  `Data: little endian`, `Machine: PowerPC`).
- Confirm the ELF was linked with `-Ttext 0x00000000` and the entry point is
  `_start`.
- The exception vector page at 0x000 (built by `ntos_entry.S`) branches to
  `HalpVectorEntry`; if `HalpInstallVectors` did not enable MSR.EE, an
  interrupt can triple-fault and reboot.

### What if no text appears?

- arcldr may have loaded the ELF but the kernel hung before display init.
- `HalpDisplayPrintf` writes to the framebuffer from `PHW_DESCRIPTION`
  (offset 28 = FrameBufferBase). If arcldr did not pass a valid loader block,
  the display uses the safe default `0xC0000000`.
- Confirm the framebuffer region is actually mapped and visible on the
  selected video mode.
- Recompile with `-O0 -g` and inspect `HalpDisplayInit` / `HalpClearScreen`
  to confirm they execute.

## Notes

- This is experimental early boot code. The kernel may hang, crash, or reboot.
- arcldr requires a Wii with the Homebrew Channel installed.
- The kernel expects entii's `PHW_DESCRIPTION` loader block in GPR r3.
- There is no shell yet; controller input is initialized but not acted on.
